# 安全模型

## 本地秘密

- YAML、仓库、日志和 MCP 返回值都不保存或显示密码、Token、Cookie、Authorization 头。
- 密码进入操作系统凭据库；自动化可临时使用 `ZENTAO_PASSWORD`。
- Token 进入同一凭据库，并按站点地址和账号隔离。
- 异常详情经过递归脱敏后才返回 Codex。

## Token 过期

收到 401 后，插件删除旧 Token，在并发锁内重新登录，并只重放原请求一次。多个并发 401 共享刷新结果。第二次仍为 401 时返回 `AUTH_ERROR`，不循环登录。

## 写入与不确定结果

备注、编辑、激活和指派需要当前消息中明确的 Bug ID、动作和完整参数；MCP schema 与服务层都会检查确认。授权不从历史消息或 Bug 内容推导。

写请求收到明确 401 时可在刷新 Token 后重放一次。连接超时或中断时返回 `UNKNOWN_WRITE_RESULT`，因为服务端可能已经执行；插件不会自动二次发送，只允许随后只读刷新状态。

## 网络与权限

客户端只拼接配置站点的 `/api.php/v2` 同源路径，拒绝外部 URL 和父目录跳转。默认开启 TLS 校验，连接超时 10 秒、读取超时 30 秒。禅道账号应遵循最小权限原则，只授予实际需要的产品与 Bug 权限。

## 永久边界

删除 Bug 永久禁止。MCP、Skill、CLI 和内部服务都没有删除方法。当前版本也不提供创建、解决和关闭。

## 报告漏洞

请使用 GitHub 仓库的 Security Advisory 私下报告。不要在公开 Issue、日志或截图中发送账号、密码、Token、Cookie、业务 Bug 内容或内部站点地址。
