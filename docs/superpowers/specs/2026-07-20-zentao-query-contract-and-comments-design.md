# 禅道按人查询、历史契约与评论开关修复设计

## 目标

修复生产环境中 `query_user_bugs` 与 `query_bug_history` 对真实禅道响应返回 `ContractError` 的问题，重新安装本地 CLI/MCP，并在项目配置中启用合规评论。修复后应能按明确指定的禅道账号查询未关闭 Bug、读取结构化历史，并让信息不足分支在全部安全门槛通过后添加一次幂等补充信息评论。

## 范围与安全边界

- 修改 `HttpZentaoProvider` 的只读响应解析和对应测试。
- 保留未知响应、缺少稳定版本、认证和权限错误的失败关闭行为。
- 不新增创建、指派、解决、关闭、激活、删除 Bug 或修改负责人/状态的能力。
- 将 `F:\每日工作\.codex\zentao-ai-bug.yaml` 中 `permissions.commentEnabled` 改为 `true`。
- 评论仍必须满足真实创建人、稳定快照、结构化历史、冷却、固定正文、确定性幂等键和 `confirm:true`；开关本身不绕过任何门槛。

## 根因调查与数据流

当前 CLI 和 MCP 均稳定复现同一问题：按中文姓名或可能的拼音账号调用 `query_user_bugs` 都在 provider 契约层失败；个人日报调用 `query_bug_history` 也被判定为不受官方契约支持。实现阶段先通过不泄露凭据的诊断测试固定真实响应的信封与字段形状，再将失败定位到 HTTP 响应到 `BugPage` / `HistoryPage` 的映射边界。

## 实现方案

1. 在 provider 单元测试中加入脱敏后的真实响应形状，分别覆盖按人列表和历史列表，并先观察测试因 `ContractError` 失败。
2. 复用现有成功解析路径，只增加已观察到的官方信封/字段别名；不允许宽松地接受任意字典或把无效响应解释为空列表。
3. 统一规范化分页数据、Bug 稳定版本、历史动作、评论标识和时间字段。分页缺失时保留已解析项目但标记覆盖未知；关键快照字段缺失时继续失败关闭。
4. 运行 provider、MCP 契约、CLI 与工作流测试，确认没有扩大写权限。
5. 从修复后的本地源码重新安装 `zentao-ai-assistant`，重启/刷新 MCP 后用真实只读调用验证四个指定账号与已知 Bug 历史。
6. 单独修改项目配置的 `commentEnabled`，重新运行配置校验；不在验证过程中发布测试评论。

## 错误处理

- 认证、权限、未知信封和缺失稳定快照返回明确且脱敏的结构化错误。
- 姓名无法解析为账号时报告身份问题，不把结果写成零条。
- 历史缺失或不完整时禁止代码修复和评论副作用，但允许生成部分完成报告。
- 重新安装失败时保留原安装并报告实际状态，不修改项目 Bug。

## 测试与验收

- 新回归测试在修复前按预期失败，修复后通过。
- `query_user_bugs` 能解析真实按人响应，返回负责人、状态、标题、版本和可信分页信息。
- `query_bug_history` 能解析真实历史响应，返回稳定的结构化动作/评论及覆盖信息。
- 未知响应仍触发 `ContractError`，不存在静默空结果。
- 完整测试套件通过，本地重新安装成功，配置校验返回 `valid:true` 且 `commentEnabled:true`。
- 对四位指定用户的真实查询结果能够区分“有结果”“确实为空”和“身份/权限失败”。
