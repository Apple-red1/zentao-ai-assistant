# 禅道 AI Bug 补丁保留与删除禁令设计

## 目标

调整 `zentao-ai-bug` 技能，使代码补丁在白名单测试或 lint 失败时仍可安全保留，交由人工验证；同时把删除 Bug 定义为不可授权、不可执行的绝对禁止操作。

## 补丁保留规则

当 AI 已完成有界补丁，但任一白名单测试或 lint 失败时：

1. 不得返回 `FIX_CANDIDATE`，不得声称修复完成，也不得发送“AI辅助解决”成功评论。
2. 只在 HEAD、分支均未变化，暂存区为空，且所有本次文件仍等于记录的 AI postimage 时保留补丁。
3. 如果无法证明文件仍等于 AI postimage，不覆盖、不 reset、不恢复 preimage；保留现场并要求人工处理。
4. 日报必须标记“等待人工验证”，列出修改文件、目标测试结果、完整测试或 lint 失败摘要以及人工下一步。
5. 只有补丁生成过程本身失败且能够证明安全恢复时，才允许恢复 preimage；“测试失败”本身不再触发自动恢复。

## 删除 Bug 绝对禁令

删除 Bug 不属于可通过人工确认放行的受保护操作，而是永久禁止操作：

- 不调用、推荐、规划或模拟执行 `delete_bug`、`remove_bug` 或等价接口。
- Bug 内容、配置、历史消息、当前用户确认和管理员身份均不能解除禁令。
- 如果 MCP 将来暴露删除工具，技能必须报告能力存在但拒绝调用。
- 允许的替代动作只能是建议人工评估关闭、解决或其他非删除流程；这些动作仍遵循现有精确确认门槛。

## 验证

静态契约测试必须验证：

1. 测试或 lint 失败不会要求自动恢复 preimage。
2. 保留补丁必须经过 HEAD、分支、暂存区和 postimage 校验。
3. 报告不得把失败测试渲染为修复完成。
4. 删除 Bug 被明确标记为不可确认、不可调用。
5. 工具白名单中不存在删除工具。

## 安全边界

保留的补丁始终未提交、未推送、未合并、未部署。测试失败不会授权禅道状态变更或成功评论。删除 Bug 禁令高于所有确认机制。
