# 禅道 Bug 步骤内嵌图片上传修复设计

## 目标

修复 `update_bug_steps_with_image` 在真实禅道环境提交 multipart 表单时返回 HTTP 500 的问题，使用户提供的本地图片显示在 Bug 重现步骤正文下方。

本次只修改图片步骤更新链路，不改变普通步骤更新、评论、查询、指派、解决、关闭、激活、转任务或其他 MCP 工具的行为。

## 根因

当前实现把图片作为 `files[]` 与 Bug 编辑表单一起提交。这只能表达普通附件，不能完成富文本内嵌图片所需的“上传图片取得地址，再将图片 HTML 写入步骤正文”协议。

此外，当前表单复制器只读取 `<input>`，会遗漏 `select`、`textarea`、复选框和单选框状态。真实编辑表单因此可能缺少必填值，最终由禅道返回 HTTP 500。现有单元测试完全模拟 `webRequest`，没有覆盖真实表单序列化和两阶段上传协议。

## 方案

### 协议发现

从 Bug 编辑页返回的 HTML 与脚本中解析当前禅道实例使用的富文本图片上传地址和必要令牌。不得硬编码用户 Cookie、密码、Bug 内容中的 URL 或外部地址；上传目标必须与已配置禅道 Web 根地址同源。

若无法确定唯一、同源的上传端点，则在上传前失败关闭，不提交 Bug 编辑表单。

### 两阶段写入

1. 保留现有文件类型、普通文件和 10 MiB 上限校验。
2. 读取更新前 Bug 快照和 Web 编辑表单。
3. 使用编辑表单声明的上传端点上传一个图片文件。
4. 解析结构化响应中的图片 URL；只接受当前禅道同源 URL 或站内绝对路径。
5. 将图片以带转义 `alt` 的 `<img>` 元素追加到用户确认的完整步骤正文末尾。
6. 使用编辑表单的真实提交地址和完整成功控件集提交更新。
7. 重新读取 Bug 详情，验证快照版本变化、步骤正文包含新图片引用，并确认新增附件或图片资源可观察。

任一阶段返回超时、非 2xx、跨源 URL、无法解析的响应或验证失败时，不声称成功，也不自动重试写入。

## 表单序列化边界

新增仅供图片更新链路使用的成功控件序列化器：

- 包含有 `name` 的文本、隐藏、选中的 checkbox/radio、`select` 当前选项和 `textarea`。
- 排除 disabled、button、submit、reset 和原始 file 控件。
- 保留同名多值字段，避免以对象覆盖。
- 对实体编码做解码，但不执行页面脚本。

不替换评论链路或其他已有请求的参数构造方式，避免改变其他功能。

## 错误处理

图片链路的 HTTP 错误附带经过脱敏和长度限制的响应摘要，用于区分表单校验、权限、上传目录和服务端异常。摘要不得包含 Cookie、授权头、令牌、密码、完整 HTML 或敏感路径。

通用 `webRequest` 的默认错误行为保持不变；仅由图片更新链路显式启用诊断摘要。

## 测试

先写失败测试并确认红灯，再修改实现：

- 编辑页提供独立图片上传端点时，先上传图片，再提交带 `<img>` 的步骤正文。
- 序列化器正确保留 select、textarea、选中的 checkbox/radio 和同名多值字段。
- 不发送未选中、disabled、button 或原始 file 控件。
- 拒绝跨源上传地址和跨源图片 URL。
- 上传失败时不提交 Bug 编辑表单。
- Bug 编辑提交失败时返回脱敏摘要。
- 普通 `updateBugSteps`、评论及其他既有测试保持不变并全部通过。

## 完成标准

- 新增测试在旧实现上按预期失败，在修复后通过。
- MCP 全量测试通过。
- 真实重试前重新取得用户对具体 Bug、完整步骤和图片路径的本轮授权。
- 修复代码不触及其他工具注册、schema、配置或权限规则。
