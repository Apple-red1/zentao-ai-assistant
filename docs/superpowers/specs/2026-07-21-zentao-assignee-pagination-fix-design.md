# 禅道负责人 Bug 分页遗漏修复设计

## 背景

禅道页面显示 Bug 2537、3397 均处于激活状态且负责人为账号 `weiwenting`。结构化详情查询也确认这两个 Bug 的负责人正确，但 `query_my_bugs` 与 `query_user_bugs("weiwenting")` 返回空列表，并给出 `total=-1`、`pages=null`。

根因位于官方 `/api.php/v2/bugs` 适配路径：服务端返回的列表缺少可验证分页元数据时，客户端在第一页后立即停止。负责人筛选在客户端执行，因此目标 Bug 不在首批数据时会被遗漏。

## 目标

- 分页元数据缺失时继续进行有界扫描，不因第一页没有目标负责人 Bug 而误报空列表。
- 保持失败关闭语义：无法证明扫描完整时继续返回 `total=-1`、`pages=null`。
- 防止无限请求：空页、重复页、跨页 ID 重叠或配置的最大页数均终止扫描。
- 保持已有合法分页元数据路径及所有安全校验不变。
- 重新安装本地 pipx 包后，以真实只读查询确认 Bug 2537、3397 可见。

## 方案

在 `_query_official_user_bugs` 中区分“分页元数据不可用”和“分页元数据矛盾”。

当元数据从第一页起不可用时，进入未知分页模式，继续请求后续页，直到出现空页、重复页、跨页 ID 重叠或达到 `_MAX_USER_BUG_PAGES`。该模式收集所有已验证为目标负责人的 Bug，但由于无法证明上游全集完整，覆盖信息保持未知。

当先前已建立可信分页契约，后续页却缺失或提供矛盾元数据时，仍立即停止并标记不完整，避免把服务端契约变化误当作正常无元数据模式。

## 测试

先新增回归测试，模拟：第一页只有其他负责人、无 `pager`；第二页出现目标负责人；第三页为空。测试必须在修改前失败，并断言修改后请求三页、返回目标 Bug，同时覆盖信息仍为未知。

保留并运行现有官方集合分页、重复页、矛盾分页、跨页 ID 重叠和最大页数测试，再运行完整测试套件与静态检查。

## 交付与验证

完成源码测试后，从该源码工作树重新安装 `zentao-ai-assistant` 到现有 pipx 环境。随后通过 MCP 执行只读个人 Bug 查询，确认返回 2537、3397；不修改 Bug、评论、状态或代码仓库以外的数据。
