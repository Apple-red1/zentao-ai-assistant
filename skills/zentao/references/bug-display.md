# Bug 编号的聊天展示

所有 Skill 面向用户的聊天回复，只要展示可识别的单个 Bug ID，就把**编号本身**渲染为指向该 Bug 的可点击链接。表格、正文、摘要、候选项和状态回报均适用，不必等用户另问“给我链接”。保持原有表头、编号文字和其余内容，不另设“链接”列代替编号链接。

## 复用基础链接命令

从本次准备展示的已有结果中提取 Bug ID，调用：

```bash
python skills/zentao/scripts/zentao.py bug web-url <id> [<id> ...] --json
```

单 ID 返回对象，多 ID 返回数组；每项含 `resource`、整数 `id`、`url`、`source`、`verified`。把单对象统一视为一项，按返回的 **`id → url`** 映射关联原结果，不能按数组位置配对。重复展示同一 Bug 可复用本次返回的 URL；不得因此重排或删除原结果。

只在最终聊天富文本中包装编号：`[123](该 id 对应的 url)`；不要把整个 Markdown 链接放进反引号或代码块，否则无法点击。表头仍可叫 `Bug ID`，正文仍可写 `Bug ID: [123](对应 URL)`，候选项仍可写 `Bug [123](对应 URL)`。URL 只能消费本命令返回值，不复制拼接逻辑或硬编码实例域名。

命令在本地生成链接，不查询 Bug、不访问页面、不打开浏览器；`verified=true` 是既有生成器字段，不代表已访问页面或确认对象存在。不要为展示链接调用 `view/list`、资源下载、页面 GET/HEAD 或浏览器，也不要执行 ZenTao 写入。命令失败或返回值无法按 ID 关联时如实说明该编号的链接生成失败，不猜 URL、不把失败标成成功，不新增恢复流程。

## 数据与流程边界

- 只链接已明确属于 Bug 的编号；混合结果中的 Task/Story/Project ID、数量及无法识别的值不能猜成 Bug ID。没有单个 Bug ID 的纯统计回复无需生成链接，也不额外查询明细。
- 查询、筛选、分页、去重、排序、标题、状态、负责人、统计口径及 `complete/partial_failures` 原样保留。
- resolver 的目标、候选、`pending_queue` 或回读状态若在聊天中展示编号，同样使用链接。仅格式化已知 ID 不表示开始处理该 Bug，不预读 pending 对象、不继续队列、不继承授权；普通证据门槛及 `HUMAN_ATTESTED_RESOLVE` 的最小流程保持不变。
- CLI `--json`、Python 原始 ID、缓存、快照、manifest、命令参数和代码示例不写入 Markdown 链接。用户要求原始机器数据时按其格式交付。
- 本规则不修改 CLI 不带 `--json` 的终端输出，也不修改 ZIP 内 `content.md` 的字段内容或批量导出格式（包括 Bug 标题和完整字段）。向用户说明导出结果的**聊天回复**仍适用。
- 本规则只管聊天展示，不改变发送到 ZenTao 的生命周期备注及任何写入合同。

新增 Skill 如会在聊天中展示 Bug ID，应从自己的 `SKILL.md` 引用本规则，继续使用同一个基础链接命令。
