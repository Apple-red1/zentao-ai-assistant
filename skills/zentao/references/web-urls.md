# 对象 Web URL 的证据与输出合同

本合同适用于全部 Skill 的回答、工作列表、报告、Issue 和生命周期备注中的对象详情链接。
API 对象存在不等于 Web 页面路由已确认。当前 CLI 没有 `object web-url` / `bug web-url`
生成器或页面验证器；不得发明该命令，也不得把任一种 URL 模式当成通用能力。

## 输出前的证据门槛

可使用的链接必须具有以下至少一种来源，并说明来源及适用范围：

- 当前实例 API / CLI 响应中明确属于目标对象详情页的 URL/link 字段。保留原值；
  任意同名字段、富文本中的历史链接或附件下载地址不等于对象详情页字段。
- 当前实例的只读页面验证结果，且页面内容确实对应目标对象。
- 当前实例配置/能力探测明确给出的路由与参数映射。只有“启用 rewrite”这一布尔值
  不足以推出 URL 模板；必须有部署路径、资源和 ID 参数的具体证据。
- 当前用户明确提供且确认可用的对象 URL 模板，按下述范围限制使用。

来源必须对应当前实例（含部署子路径）和资源类型，不能借另一个对象的 URL 改 ID
推导通用模板。URL/link 字段或模板证明的是链接来源，不等于已经逐页访问成功；
只有实际只读验证目标对象页后才能声称页面已验证或标记 `verified=true`。
这些是 Agent 的报告规则，不是新增的 API JSON 字段；CLI 保持原始领域数据合同。

对象导航只接受不含凭证的 HTTP(S) 地址；不把跨实例链接、密码、Token 或认证参数
输出为可用导航。相对地址必须有明确的当前实例解析基准；不能猜基准路径。

## 场景规则

### 只有 ID

API 只返回 Bug ID、没有对象 URL 字段时，不生成 `/bug-view-<ID>.html`，也不生成
`/index.php?m=bug&f=view&bugID=<ID>`。对象 ID 与 API base URL 不足以证明 Web 路由。
已确认的多个 Bug 逐项列出 ID 和链接不可用说明，不能为了凑齐链接而补猜测。

### 历史示例

历史文档、测试 fixture、截图或另一部署中的 `/bug-view-123.html` 不是当前实例证据。
这些只能作为示例文本，不能推导当前路由；用户指出链接错误后不改猜另一种路由。

### 传统 query route

`/index.php?m=bug&f=view&bugID=<ID>` 不是默认回退。必须有当前实例的明确链接或
模板证据才可按来源输出；只有只读验证页面对应目标对象后才可称“页面已验证”。

### 伪静态 rewrite route

`/bug-view-<ID>.html` 不是通用模板。必须有当前实例的明确链接或模板证据才可
按来源输出；只有只读验证页面对应目标对象后才可称“页面已验证”。

### HTTP 200 假成功

HTTP 200、HEAD 成功或重定向结束不能单独证明对象页有效。必须检查最终地址与
页面内容确实属于目标资源及 ID；登录页、首页、软 404、权限错误或其它对象页
均不能标记 `verified=true`。无法检查内容时保持未验证，不把探测失败换成猜路由。

### 子路径部署

例如实例部署在 `/zentao/` 时，不得丢失来源中的部署前缀、路径或查询参数，
不得把相对模板擅自拼到域名根目录。缺少解析基准或来源范围不匹配时返回不可可靠生成，
不能通过无条件加/删 `/zentao/` 修正未经验证的地址。

### 无法验证

没有上述证据或当前工具无法可靠判断时，输出：

```text
已确认 Bug ID：3647
页面 URL：当前能力无法可靠生成/尚未验证
```

只有实际读取或已有可靠对象证据才写“已确认”；用户仅给 ID 时写“用户提供的 Bug ID”。
如用户明确需要排查候选格式，只能用代码文本并标注“候选格式（未验证）”，
不得将其包装成可点击的已确认链接，也不得说“正确地址是”。默认不提供候选地址。

### 用户已验证模板

用户明确确认模板在当前实例可用时，只在当前请求和指定资源类型内替换明确的 ID
占位符，保留部署前缀及其它参数。标注“来源：用户确认的模板；未逐页验证”；
不得宣称 Agent 已逐页验证，不得跨实例、跨资源、跨请求复用或存成全局默认路由。
用户只给一个链接但未授权其作为模板时，不从该链接推导其它 ID 的地址。

## API 与执行边界

内部工作流优先记录 `instance/base_url + resource=bug + id=<ID>`；instance/base_url
保留部署范围但不包含认证秘密。Web 页面 URL 不作为 API 操作的事实源。
对象读取仍使用现有入口：

```bash
python skills/zentao/scripts/zentao.py bug view <id> --json
```

`resource fetch` 只用于对象关联附件/富文本资源，不是任意页面探测器；不得用它
绕过输入范围、同源校验或权限。高层 Skill 仍不得直连 HTTP/Internal。没有可用的
只读页面验证工具时直接说明能力不可用，不新增 endpoint、不调用私有接口、不自动写入。
链接不可用不改变对象读取结果，也不增加 resolver 普通/人工确认分支的生命周期门槛。
